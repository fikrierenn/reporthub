## Oturum 5 — sqlserver-mcp-server güvenlik hardening + Windows PATH fix

### Ana Konu

Oturum 4'teki Zirve MCP eklemesi sonrası, kullanıcı `D:\Dev\sqlserver-mcp-server` projesini "kontrol et hatırlamıyorum" diye sorunca eksik analizi yaptım: multi-statement DOS bypass'ı, connection error'da credential sızıntısı, 0 test, no CI/lint. ### Tamamlananlar

**sqlserver-mcp-server hardening (commit `d1729b8` + `3bac1b5` master branch):**
- `splitStatements()` — yorum + string literal aware T-SQL batch parser. `SELECT 'a;b'` tek statement, `SELECT 1 /* foo;bar */` tek statement, `SELECT 'a''b;c'` (escape '') tek statement.
- `isMultiStatementAllowed()` — default false. Multi-statement DOS (`SELECT 1; WAITFOR DELAY '00:01'`) ve write bypass (`SELECT 1; UPDATE Foo`) kapatıldı.
- `sanitizeError()` — `Error.message` + `originalError.message` zinciri içinde MSSQL_PASSWORD ve MSSQL_HOST'u `[REDACTED]` ile maskeler.
- `executeQuery()` başında multi-statement guard + getPool/runQuery catch'lerinde sanitize.
- 33 unit test (24 database + 7 query, hepsi yeşil).
- `.env.example` ALLOW_MULTI_STATEMENT eklendi.
- README "Güvenlik katmanları" 7 maddelik bölüm.
- `tsconfig.json` build sırasında `*.test.ts` exclude.
- `.github/workflows/ci.yml` — install (--ignore-scripts) + build + test.
- **Refactor d1729b8 → 3bac1b5:** vitest + ESLint + Prettier dropped, `node --test` + `tsx` loader (sıfır external test bağımlılığı). Postinstall (esbuild binary download) Windows'ta `'node' is not recognized` veriyordu, çözüm: dış paket bağımlılığı yok.

**Windows PATH truncation kanıtı:**
- `npm test` ve `tsc` "node not recognized" hatası verdi rağmen `where node` çalışıyordu.
- Root cause: User PATH 87 entry / 4020 char, Machine PATH 89 entry / 4095 char — toplam 8115, Windows %PATH% limitine (8191) çok yakın. cmd.exe spawn'da PATH truncate, npm scripts node'u bulamıyor.
- Geçici fix (set PATH=C:\Windows\system32;...;C:\Program Files\nodejs) ile testler 33/33 geçti — kanıt tamam.

**`scripts/fix-path.ps1` yazıldı (uncommitted):**
- Dry-run + apply mode. User scope (default) ve `-Machine` System scope.

- Case-insensitive trailing-slash normalize ile duplicate kaldırma.
- Var olmayan klasörleri raporlar ama silmez (network drive olabilir).
- Apply sırasında eski PATH'i `~\path-backup-<scope>-<timestamp>.txt` dosyasına yedekler.
- Kullanıcı dry-run sonuçları: User PATH 87 → 46 entry (-47%), Machine PATH 89 → 64 entry (-28%).
